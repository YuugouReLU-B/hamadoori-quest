# 紹介クエスト｜クエスト作成と本番反映手順

紹介URL（`?ref=<code>`）経由の新規登録で、**紹介した人と紹介された人の両方に50P**が入るようにするための、クエスト側の設定手順。

このドキュメントが扱うのは **クエスト2件の設定値と、その本番反映のやり方** だけ。付与ロジック（RPC や登録フローの改修）は別の変更で扱う。

前提として、`mission_artifacts` の artifact type に `REFERRED` を追加するマイグレーション
`supabase/migrations/20260924100000_add_referred_artifact_type.sql` が適用済みであること。

---

## 1. 両クエストの設定値一覧

### ① 紹介した側（紹介者）: 既存 `slug = 'referral'` を **書き換えて** 使う

新規作成しない。`supabase/migrations/20250607041000_add_referral_mission.sql` が
`id = 'f570446b-b1fd-f456-fc4b-935c2b493089'` で挿入し、
`20250624081700_add_slug_to_missions.sql` が `slug = 'referral'` を付与している既存クエスト。
マイグレーションを流したDBには必ず存在する。

| 項目 | 設定値 |
| --- | --- |
| slug | `referral`（**変更しない**） |
| required_artifact_type | `REFERRAL`（**変更しない**） |
| title | 友だちに浜通りクエストを紹介しよう |
| content | あなた専用の紹介URLを友だちに共有しよう。紹介URLから登録が完了すると、自動で達成になります。 |
| quest_category | `SNS` |
| event_category | `NULL` |
| icon_url | `/img/mission-icons/refer-a-friend.png` |
| difficulty | `1` |
| points | `50` |
| max_achievement_count | `NULL`（**無制限**。何人紹介しても達成できる） |
| is_featured | `false` |
| is_hidden | `false` |

> **なぜ新規作成しないのか**
> `achievements.mission_id` の外部キーは `ON DELETE` 無指定（NO ACTION。
> `supabase/migrations/20250510122416_add_first_tables.sql` 187行目付近）。
> 既に達成データがあるクエストは削除できないため、作り直すと重複する。
> よって **既存行を UPDATE する**。

### ② 紹介された側（被紹介者）: `slug = 'referred-signup'` を **新規作成**

`mission_data/missions.yaml` に定義済み。

| 項目 | 設定値 |
| --- | --- |
| slug | `referred-signup` |
| required_artifact_type | `REFERRED` |
| title | 紹介されて浜通りクエストを始めよう |
| content | 友だちの紹介URLから登録すると自動で達成になります。 |

> **なぜ `is_hidden: true` なのか**
> 紹介URLから登録した瞬間に自動で達成になるクエストで、ユーザーが一覧から選んで
> 挑戦するものではないため。一覧に出すと「どうやって達成するのか分からない」状態になる。

## 2. 既存 `slug = 'referral'` の書き換え手順

**① 管理画面から** と **② SQL から** の2通りを載せる。
**本番でどちらを使うかは依頼者が判断する。** どちらでも結果は同じ。

### ① `/admin` から行う手順

1. 管理者アカウントでログインし、`/admin/missions` を開く。
2. 一覧から **「チームみらいの仲間を増やそう」**（= `slug: referral`）を探して編集を開く。
   - 既にタイトルを変更済みの場合は `slug` が `referral` のものを探す。
3. 次の項目を「1. 両クエストの設定値一覧 ①」の表のとおりに変更する。
   - タイトル → `友だちに浜通りクエストを紹介しよう`
   - 説明文（content） → `あなた専用の紹介URLを友だちに共有しよう。紹介URLから登録が完了すると、自動で達成になります。`
   - クエストカテゴリ → `SNS`
   - イベントカテゴリ → 未設定（空）
   - アイコンURL → `/img/mission-icons/refer-a-friend.png`
   - 難易度 → `1`
   - ポイント → `50`
   - 最大達成回数 → **空欄（無制限）**
   - 注目 → オフ
   - 非表示 → オフ
4. **slug と 提出物種別（required_artifact_type = `REFERRAL`）は触らない。**
5. 保存後、`/dev/missions` で「紹介」と表示されること、最大達成回数が「無制限」であることを確認する。

> 注意: 最大達成回数を空欄にできない画面仕様の場合は、②のSQLで `NULL` にすること。
> `1` のまま残すと2人目以降の紹介で達成が付かない。

### ② SQL で行う場合の UPDATE 文

ローカル（`postgresql://postgres:postgres@localhost:54322/postgres`）で実際に使ったものと同じ。
本番で実行する場合は接続先だけ差し替える。

```sql
UPDATE missions
SET
  title = '友だちに浜通りクエストを紹介しよう',
  content = 'あなた専用の紹介URLを友だちに共有しよう。紹介URLから登録が完了すると、自動で達成になります。',
  quest_category = 'SNS',
  event_category = NULL,
  icon_url = '/img/mission-icons/refer-a-friend.png',
  difficulty = 1,
  points = 50,
  max_achievement_count = NULL,
  is_featured = false,
  is_hidden = false
WHERE slug = 'referral';
```

`slug` と `required_artifact_type` は SET に含めない（変更しないため）。

適用後の確認:

```sql
SELECT slug, title, required_artifact_type, points, max_achievement_count,
       is_hidden, is_featured, icon_url, quest_category
FROM missions
WHERE required_artifact_type IN ('REFERRAL', 'REFERRED')
ORDER BY required_artifact_type;
```

`REFERRAL` が1行、`REFERRED` が1行、それぞれ上記の値で返ること。

## 3. `referred-signup` の作成手順

`mission_data/missions.yaml` に定義済みなので、**新規環境では `mission:sync` で入る**。

```bash
# 何が挿入されるかを先に確認（DBは変更しない）
pnpm run mission:sync:dry

# 実際に挿入
pnpm run mission:sync
```

> **`mission:sync` は挿入のみ。既存クエストの更新はしない。**
> すでに `referred-signup` が存在する環境で値を変えたい場合は、
> 管理画面（`/admin/missions`）かSQLで直接更新すること。

既存環境にSQLで入れる場合:

```sql
INSERT INTO missions (
  slug, title, content, quest_category, event_category, icon_url,
  difficulty, required_artifact_type, points, max_achievement_count,
  is_featured, is_hidden, artifact_label, ogp_image_url
)
VALUES (
  'referred-signup',
  '紹介されて浜通りクエストを始めよう',
  '友だちの紹介URLから登録すると自動で達成になります。',
  'SNS',
  NULL,
  '/img/mission_fallback.svg',
  1,
  'REFERRED',
  50,
  1,
  false,
  true,
  NULL,
  NULL
)
ON CONFLICT (slug) DO NOTHING;
```

## 4. マイグレーション適用手順

```bash
# 未適用のマイグレーションだけを流す（本番・ステージング想定）
pnpm run db:migrate

# ローカルをまっさらに作り直す（全マイグレーション + seed + mission:sync）
pnpm run db:reset
```

今回追加したのは1ファイル:

- `supabase/migrations/20260924100000_add_referred_artifact_type.sql`
  - `mission_artifacts` の `check_artifact_type` と `ensure_artifact_data` を DROP → ADD で作り直し、`REFERRED` を許可する。
  - `REFERRED` の条件は `REFERRAL` と同形（`text_content IS NOT NULL` / `link_url IS NULL` / `image_storage_path IS NULL`）。
  - 既存の許可値（LINK, TEXT, EMAIL, IMAGE, IMAGE_WITH_GEOLOCATION, REFERRAL, POSTING, POSTER, QUIZ, LINK_ACCESS, YOUTUBE, YOUTUBE_COMMENT, RESIDENTIAL_POSTER）は1つも落としていない。

> ### ⚠️ `db:reset` すると `referral` の書き換えは消える
> `db:reset` は全マイグレーションを流し直すため、`slug = 'referral'` は
> `20250607041000_add_referral_mission.sql` が挿入した **元の内容（title「チームみらいの仲間を増やそう」等）に戻る**。
> クエスト内容はDBが正、という方針からマイグレーションには書き換えを含めていない。
> **`db:reset` のたびに「2. ②」の UPDATE を再適用すること。**

### 制約が効いているかの確認（任意）

`BEGIN` 〜 `ROLLBACK` で囲むので、DBには何も残らない。

```sql
BEGIN;

-- テスト用ユーザーは auth.users から取る（新規にユーザーを作らない）
CREATE TEMP TABLE _fixture ON COMMIT DROP AS
SELECT
  (SELECT id FROM auth.users ORDER BY created_at LIMIT 1)   AS user_id,
  (SELECT id FROM missions WHERE slug = 'referral' LIMIT 1) AS mission_id;

CREATE TEMP TABLE _ach ON COMMIT DROP AS
WITH ins AS (
  INSERT INTO achievements (mission_id, user_id)
  SELECT mission_id, user_id FROM _fixture
  RETURNING id
)
SELECT id FROM ins;

-- (a) REFERRED かつ text_content あり → 通る
INSERT INTO mission_artifacts (achievement_id, user_id, artifact_type, text_content)
SELECT a.id, f.user_id, 'REFERRED', 'referred-test@example.com'
FROM _ach a, _fixture f;

-- (b) 同じFKのまま text_content = NULL → ensure_artifact_data で弾かれる
INSERT INTO mission_artifacts (achievement_id, user_id, artifact_type, text_content)
SELECT a.id, f.user_id, 'REFERRED', NULL
FROM _ach a, _fixture f;

ROLLBACK;
```

(b) で次のエラーが出れば正しい。FK違反ではなく **CHECK違反**で、制約名が `ensure_artifact_data` であることを確認する。

```
ERROR:  new row for relation "mission_artifacts" violates check constraint "ensure_artifact_data"
```

> **つまずきやすい点（実際に踏んだもの）**
>
> 1. **テスト用ユーザーは `auth.users` から取ること。**
>    `achievements.user_id` の FK 先は `public_user_profiles` だが、
>    ローカル環境では `public_user_profiles.id` と `auth.users.id` が一致しないことがある。
>    `public_user_profiles` から取ると
>    `violates foreign key constraint "achievements_user_id_fkey" … is not present in table "users"`
>    になる。
> 2. **`GET STACKED DIAGNOSTICS … PG_EXCEPTION_CONSTRAINT` は使わない。**
>    この環境の PostgreSQL では `unrecognized GET DIAGNOSTICS item` になる。
>    上記のように素の `INSERT` を実行して、エラーメッセージの制約名を目視で確認する。

## 5. 本番反映時の確認事項

反映後、次のSELECTで確認する。

```sql
SELECT slug, title, required_artifact_type, points, max_achievement_count,
       is_hidden, is_featured, icon_url, quest_category
FROM missions
WHERE required_artifact_type IN ('REFERRAL', 'REFERRED')
ORDER BY required_artifact_type;
```

チェックリスト:

- [ ] `required_artifact_type = 'REFERRAL'` の行が **ちょうど1件**（増えていない＝新規作成してしまっていない）
- [ ] その `max_achievement_count` が **`NULL`（無制限）**。`1` のままだと2人目以降の紹介で達成が付かない
- [ ] その `points` が `50`、`is_hidden` が `false`、`icon_url` が `/img/mission-icons/refer-a-friend.png`
- [ ] `required_artifact_type = 'REFERRED'` の行が **ちょうど1件**
- [ ] その `max_achievement_count` が **`1`**、`points` が `50`
- [ ] その `is_hidden` が **`true` のまま**（ユーザーの一覧に出さない）
- [ ] `slug` と `required_artifact_type` を書き換えていない
- [ ] **既存クエストを削除していない**（`achievements.mission_id` の FK は `ON DELETE` 無指定のため、達成データがあると削除できない。削除ではなく UPDATE で対応する）
- [ ] マイグレーション `20260924100000_add_referred_artifact_type.sql` が適用済み

## 6. 文言の注記（3つの使い分けは意図的）

似た言葉が3つ出てくるが、**役割が違うので統一しない**。

| 文言 | どこに出るか | 誰向けか |
| --- | --- | --- |
| **紹介されて開始** | `ARTIFACT_TYPES.REFERRED.displayName`（`src/lib/types/artifact-types.ts`） | 開発者向け。artifact type の表示名 |
| **被紹介** | `/dev/missions` の提出物種別ラベル（`src/app/dev/missions/page.tsx` の `ARTIFACT_TYPE_LABELS`） | 開発者向け。一覧に収まる短いラベル |
| **紹介されて浜通りクエストを始めよう** | クエストの `title`（DBの `missions.title`） | **ユーザーに見える文言**。達成履歴にもこれが出る |

紹介した側も同様に、artifact type の displayName は「紹介クエスト」、`/dev/missions` ラベルは「紹介」、
ユーザーに見える title は「友だちに浜通りクエストを紹介しよう」で、それぞれ別物。
