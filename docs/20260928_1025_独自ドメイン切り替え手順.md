## 前提

- `hamadoori-circle.com` は東北新社がお名前.comで管理している（NS: `01〜04.dnsv.jp`）。
  apex は studio.design（A `34.111.141.225`）、MX は Google。**apex・MX・TXT には触らない。**
- 2026-09-28 に東北新社（畑山様）へ、次のDNSレコード追加を依頼済み。
  - 第一候補: `quest` CNAME `2aeafd7a76fa86fb.vercel-dns-016.com`
  - 予備: `quest` A `216.150.1.1` / `216.150.16.1`
- Vercel 側（team `relu-branch` / project `hamadori-quest`）は準備済み。
  - `quest.hamadoori-circle.com` はプロジェクトに登録済み（`verified: true`、TXT認証不要）
  - 本番デプロイのエイリアスに付いている
  - CAA なし・ワイルドカードなし・DNSSEC 未署名（証明書発行の妨げなし）
- Vercel CLI は「`hamadoori-circle.com` を設定しろ（A を 76.76.21.21 に／NS を Vercel に）」と警告を出す。
  **無視すること。** 先方に依頼すると studio.design のサイトとメールが止まる。

## DNSが反映されても既存の本番は壊れない

`hamadori-quest.vercel.app` はそのまま動き続ける。
新ドメインは開けるが、下の「事前にやること」「切り替え当日」が済むまで一部の機能がおかしい。
**新ドメインは切り替え当日の作業が終わるまで案内しない。**

切り替え前に新ドメインで使うと起きること:

| 機能 | 症状 | 原因 |
|---|---|---|
| LINEログイン | ログインは成功するが vercel.app に移る。紹介・キャンペーン計測と戻り先が落ちる | `redirect_uri` が `APP_ORIGIN`（vercel.app）固定。state 等の cookie はホスト限定 |
| 地図（Google Maps） | 表示されない | APIキーのHTTPリファラ制限に新ドメインが無い（2026-09-28 に 403 を確認） |
| OGP・招待URL | vercel.app のURLになる | `APP_ORIGIN` 由来 |

## 切り替え当日

先方から「設定した」と連絡が来てから行う。**3〜5 は間を空けずに続けて行う。**

1. DNS と証明書を確認する
   ```bash
   dig +short quest.hamadoori-circle.com
   vercel domains inspect quest.hamadoori-circle.com --scope relu-branch
   curl -sI https://quest.hamadoori-circle.com/ | head -3   # 200 と証明書エラーなし
   ```
2. 「事前にやること」#2・#3 が済んでいることを確認する
3. Vercel の Production 環境変数 `NEXT_PUBLIC_APP_ORIGIN` を `https://quest.hamadoori-circle.com` に変え、**本番を手動で再デプロイ**する
   - `NEXT_PUBLIC_*` はビルド時に埋め込まれるので、再デプロイしないと反映されない
   - 手順は [本番デプロイ手順メモ](20260913_1618_本番デプロイ手順メモ.md)
4. GitHub Variables `SITE_URL` を `https://quest.hamadoori-circle.com` に変え、`supabase config diff` で差分を確認してから main へ push（または `deploy.yml` を workflow_dispatch）して Supabase に反映する
5. `hamadori-quest.vercel.app` を新ドメインへ 308 リダイレクトにする
   ```bash
   vercel api -X PATCH "/v9/projects/prj_NwqZxo4VPx77jPr3JUKczSIwYLg5/domains/hamadori-quest.vercel.app?teamId=team_QPb9uf7Cy7HHzjBN7YGaDxRe" \
     --input - <<< '{"redirect":"quest.hamadoori-circle.com","redirectStatusCode":308}'
   ```
   （ダッシュボードの Settings → Domains からも設定できる）
6. 動作確認（新ドメインで）
   - LINEログイン（`?ref=` / `?cv=` 付きで入って引き継がれるか、戻り先）
   - 地図の表示
   - OGP（シェアURLのプレビュー）
   - 旧URL `https://hamadori-quest.vercel.app/<任意のパス>` が新ドメインの同じパスへ飛ぶこと
7. ✅ Vercel の Production 環境変数 `SITE_URL` / `ADDITIONAL_REDIRECT_URLS` もそろえておく（コードからは読まれていないが、値の食い違いを残さないため）
8. [本番デプロイ手順メモ](20260913_1618_本番デプロイ手順メモ.md) と CLAUDE.md の本番URLを新ドメインに更新する

## 注意

- **vercel.app のドメインは削除しない。** 配布済みのリンク・QR・SNS投稿が切れる。リダイレクトとして残す。
- 既存ユーザーは cookie がホスト限定のため、新ドメインで1回ログインし直しになる。
  アクセス解析の visitor_id も振り直しになり、切り替え直後はユニーク訪問者が二重計上される。
- アプリ内QRスキャナ（`/scan`）は、読み取ったURLのオリジンが今のページと一致しないと弾く
  （`src/features/qr-spot/components/qr-scanner.tsx` の `toSpotPath`）。
  印刷済みの vercel.app のQRは新ドメインのスキャナでは読めなくなる。
  2026-09-28 時点でQR機能は使っていないため対応を見送った。使う場合は旧オリジンも許可する修正が必要。
  管理画面でQRを「作り直し」すると旧印刷物が無効になるので、ドメイン変更を理由に再発行しないこと。
- MCPクライアントなど、外部に vercel.app のURLを登録しているものがあれば新ドメインに差し替える
  （リダイレクトで動く場合もあるが、POST を 308 で追従しないクライアントがある）。

## 切り替え後の確認（2026-09-28）

- ブラウザ（Playwright・iPhone 13）で旧URL→新ドメイン、紹介コードcookieが新ドメインに付く、Google Maps表示、LINEログイン画面への遷移（`redirect_uri` 新ドメイン）を確認
- 公開ページ・JSチャンク・APIレスポンスに `vercel.app` の参照なし。旧ドメインは GET/POST とも 308 でパス・クエリ維持
- DBに旧ドメインが残るのは `analytics_events` の過去ログのみ
- ログインはLINEのみ。パスワードリセット・メール変更は利用者の導線に無いため確認対象外
- 残り（手動）: LINE公式アカウントのリッチメニュー等のリンク書き換え。落ち着いたらLINE DevelopersのvercelアプリのコールバックURLを削除
- `hamadori-quest-relu-branch.vercel.app` はリダイレクトされずにアプリを返す（noindex）。ここからLINEログインするとstate cookieが別ホストになり失敗する見込み。案内しないこと

## 切り替えと無関係に見つかった点

`supabase config diff` で、本番の `auth.sms.twilio.enabled` が `true`、`config.toml` では `false` になっている。
`config push` はこの値を書き換えられない（ワークフローログに明記）ので、変えるならダッシュボードで。
- ミッション `add-supporter-line-friend` の `ogp_image_url` が派生元の別Supabaseプロジェクト（`tibsocpjqvxxipszbwui`）を指している。
